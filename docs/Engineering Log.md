- **Three Windows defects in `iai-pme` 3.0.4 had to be fixed locally to get that working - documented at `~/.iai-mcp/local-patches/README.md` and SELF-HEALING: `ensure_patches.py` detects each bug by its broken code pattern (no-op once upstream fixes it) and runs from `daemon-start.cmd` before every boot, so a package update that overwrites site-packages is re-healed at the next daemon start; `backup/` there holds the crypto key, task XML, and hooked settings.json. Caveat: `daemon install` regenerates daemon-start.cmd, dropping the guard line - see the README.** (1) `daemon/__init__.py` `_install_boot_signal_trace` iterates `(signal.SIGTERM, signal.SIGINT, signal.SIGHUP)` - the tuple is built before the loop body, so the per-signal `except AttributeError` guard never fires and the Windows-absent `SIGHUP` killed the daemon at boot. (2) The real one: `socket_server.py` `SocketServer.serve` probed `inspect.signature(asyncio.start_unix_server)` ABOVE its `if IS_WINDOWS:` branch, and asyncio exposes `start_unix_server` only where AF_UNIX exists - so every Windows boot raised AttributeError before the loopback bind. `serve()` is scheduled fire-and-forget, so it failed SILENTLY: the daemon booted, warmed, ticked its FSM and served nothing; `.daemon.port` was never written, every client reported "daemon not running", `iai recall` degraded to a substring bank-scan (0.000-score, off-target hits) rather than erroring, and the watchdog killed the process `reason=wedge` at the 600s cold-start grace on every boot. Fix is to move the POSIX capability probe below the Windows `return`. (3) `iai-mcp daemon install` generates a Task Scheduler XML whose `<LogonTrigger>` and `<Principal>` carry no `<UserId>`, which Windows reads as "at logon of ANY user" and therefore requires elevation - `schtasks /Create` returns "Access is denied" for a normal user. The task `iai-mcp-daemon` here was registered by hand from a patched XML pinning both to this user; `daemon start/stop/status/uninstall` address the task by name and work against it normally. All three are worth reporting upstream - the README explicitly asks for Windows issues and PRs.
